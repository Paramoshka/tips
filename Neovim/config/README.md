# Neovim: Go, Helm и Kubernetes

Конфигурация для Neovim 0.11.0. После изменений перезапусти Neovim.
`<Space>` — leader; меню сочетаний открывается после пробела.

## Основные клавиши

| Клавиши | Действие |
| --- | --- |
| `<Space>e` | Файлы проекта |
| `<Space><Space>` | Быстрый поиск файлов |
| `<Space>/` | Поиск текста |
| `<Space>cs` | Структура файла справа |
| `<Space>xx` | Панель диагностики |
| `<Space>tt` / `<Space>tf` | Ближайший Go-тест / тесты файла |
| `<Space>tl` / `<Space>tS` | Повторить / остановить тест |
| `<Space>ts` / `<Space>to` | Дерево тестов / вывод теста |
| `<Space>tO` | Общая панель вывода тестов |
| `<Space>td` | Отладить ближайший тест через Neotest |
| `F9` / `F5` | Breakpoint / начать или продолжить отладку |
| `F10` / `F11` / `F12` | Шаг через / внутрь / наружу |
| `<Space>du` / `<Space>de` | Панели отладки / вычислить выражение |
| `<Space>dB` / `<Space>dq` | Условный breakpoint / завершить отладку |
| `<Space>sp` | Поиск и замена по Git-проекту |
| `<Space>qs` / `<Space>qS` | Восстановить / выбрать сессию |
| `<Space>ql` / `<Space>qd` | Последняя сессия / не сохранять текущую |
| `<Space>or` / `<Space>ot` | Запустить задачу / открыть панель задач |
| `<Space>gg` | Lazygit |
| `<Ctrl-/>` | Терминал снизу |

Сессии сохраняются при выходе после открытия файла, восстанавливаются вручную.
В Grug Far сначала просмотри совпадения; `\r` применяет замену
(локальный leader — обратный слеш). Все действия показаны в подсказке окна.

## Helm и диагностика

Шаблоны в `templates/` используют filetype `helm`, Helm LS и Treesitter.
Подсказки, документация и переходы работают через Helm LS. Обычные YAML
по-прежнему проверяет `yamlls`.

Экспериментальная YAML-диагностика внутри Helm LS отключена: в шаблонах
Deckhouse взаимоисключающие ветки дают ложные сообщения о повторяющихся ключах.
Это не проверка отрендеренного манифеста. Для проверки шаблонов используй
принятые в проекте template tests и lint; диагностика Helm lint не отключена.
Тексты ошибок в редакторе показываются на текущей строке, остальные доступны
в панели диагностики и по `<Space>cd`.

## Тесты и совместимость

Neotest запускает обычные Go-тесты и подтесты через `neotest-golang` v1.
Обнаружение файлов запускается по запросу, без фонового сканирования всех
модулей репозитория. Таймаут Go-тестов — 60 секунд; при необходимости измени
`go_test_args` в `lua/plugins/testing.lua` под свой проект.

Ginkgo-сценарии `Describe`/`It` не получают отдельного дерева в этом Go-адаптере:
их запускают принятыми в проекте командами, например через задачи или терминал.
Инфраструктурные e2e-тесты автоматически не запускаются.

`nvim-dap` закреплён на 0.10.x, `neotest-golang` — на 1.x для совместимости
с Neovim 0.11.0 и текущей веткой Treesitter. Точные коммиты — в `lazy-lock.json`.
Версии остальных ранее установленных плагинов сохранены.
Helm LS устанавливается через Mason; для его работы нужен `helm`, а для YAML —
`node`/`npm` и `yaml-language-server`. Delve устанавливается через Mason, если
доступен `go`. Для Go-тестов и отладки нужен Go, для подсказок Go — `gopls`.
Для `Space gg` отдельно установи `lazygit` и добавь его в `PATH`.
В C-проектах используются `clangd` и `clang-format`.

При переносе нужны Neovim 0.11+, Git, C-компилятор, make, curl, unzip и ripgrep.
Для установки Ruff через Mason нужен `python3-venv`. Дополнительные серверы,
для которых нет подходящего инструмента, можно установить позже.
На первом запуске плагины и инструменты загружаются из сети; дождись установки
и перезапусти Neovim. Точные версии плагинов включены в `lazy-lock.json`.
